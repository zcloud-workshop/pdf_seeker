# v0.3 中期目标实施计划

> 对应 `README.md` roadmap「中期（v0.3）」五项。本文档是本次实施的单一任务追踪来源，每完成一项勾选对应 checkbox。

## 背景与目标

v0.2（页面拖拽排序、表格提取 CSV、撤销/重做、批量导入、暗色预览优化）已合并 main（`6e0432e`）。v0.3 目标为五个进阶编辑能力：

1. PDF 页面内容编辑（替换文本）
2. PDF 表单填写
3. PDF 批注（高亮、下划线、便签）
4. PDF 安全（加密/解密、密码保护）
5. 页面裁剪

## 总体策略

- **分支**：`feat/v0.3-mid-term-goals`，每功能一个 commit，完成后开 PR 合并 main（沿用 v0.2 流程）。
- **改动路径**（v0.2 模式，每功能 5 处）：
  1. `src-tauri/src/commands/pdf_ops.rs`：camelCase 请求结构体 + `#[tauri::command]`
  2. `src-tauri/src/lib.rs`：`invoke_handler!` 注册
  3. `src/views/Tools.svelte`：`ToolId` / `toolDefs` / execute / 面板模板
  4. `src/lib/i18n/locales/zh.json` + `en.json`：labelKey
  5. `README.md`：功能表 + roadmap 勾选
- **验证标准**：`cd src-tauri && cargo test` 全绿；`npm run check` 不劣化存量基线（2 错误 5 警告，系 v0.3 之前已存在）；每功能手动冒烟一遍。
- **实施顺序**（由易到难，风险最高放最后）：页面裁剪 → 批注 → 表单填写 → 替换文本 → 加密/解密。

## 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 替换文本方式 | **覆盖式**（原位盖白色矩形 + Helvetica 同字号叠加新文本） | 复用 `add_rectangle`/`add_text_to_page` 机制，所有 PDF 通用、位置精确；内容流级真替换受子集字体编码限制，通用不可行 |
| 加密标准 | **AES-128**（标准安全 handler R4/V4，AESV2 crypt filter） | 现代阅读器全支持，安全性与复杂度平衡；lopdf 不支持写加密，需自行实现 |

## 功能 1：页面裁剪 ✅

**目标**：在预览画布上拖拽选区，将页面裁剪为该区域（当前页或全部页）。

**范围**：设置页面 `/CropBox`；不改动 `/MediaBox`、不重采样内容。

**技术方案**：
- 后端 `crop_pages(req { inputPath, outputPath, pages: Vec<u32>, x, y, width, height })`：坐标为 PDF 点（左下原点），校验选区非空且在 MediaBox 内后写 `/CropBox`；沿用 `get_page_size` 的页面字典访问模式。
- 前端：裁剪工具 `crop`（hasPreview），预览画布拖拽选区 → 坐标换算（viewport 翻转 y 轴）→ 当前页/全部页二选一 → `applyEditInPlace`（可撤销）。

**任务清单**：
- [x] 后端命令 + 单测（crop 后重载断言 CropBox 值；越界选区报错）
- [x] 前端工具面板 + 拖拽选区交互 + applyEditInPlace
- [x] i18n（zh/en）+ README 功能表 + roadmap 勾选

**验收**：裁剪当前页与全部页均生效；Cmd+Z 可撤销；`cargo test` 全绿。

## 功能 2：PDF 批注（高亮、下划线、便签）

**目标**：写入真实 PDF 批注对象（`/Annots`），在其他阅读器中可识别、可管理。

**范围**：三种类型——高亮（拖拽选区）、下划线（拖拽选区）、便签（点击 + 文字）；不做批注的再编辑/删除（由其他阅读器完成）。

**技术方案**：
- 后端 `add_annotation(req { inputPath, outputPath, page, annotType: "highlight"|"underline"|"note", rect, color, opacity, content })`：
  - 写 `/Annots` 数组追加批注字典：`/Subtype /Highlight | /Underline | /Text`、`/Rect`、`/IC`（颜色）、`/Contents`（便签文字）、`/F 4`（打印标志）；
  - 生成 `/AP` 外观流：高亮 = 半透明填充矩形（`/CA`/`gs` 或 `rg`+`Tr`）；下划线 = 底边线条；便签 = 矩形底 + 折角 + `Tj` 文字缩略。
- 前端：批注工具 `annotate`（hasPreview），选区/点击交互，颜色与不透明度可调，走 `applyEditInPlace`。

**任务清单**：
- [ ] 后端命令 + 单测（断言 /Annots 存在、Subtype/Rect 正确）
- [ ] 前端工具面板（类型切换、颜色、便签文字输入）
- [ ] i18n + README 同步

**验收**：三种批注在预览与外部阅读器（如 macOS 预览）中均可见；可撤销。

## 功能 3：PDF 表单填写

**目标**：读取 AcroForm 表单字段并填写，另存新文件。

**范围**：文本框、复选框；单选/下拉在 UI 可选（按 /Opt 写值）；不生成外观流（设 `/NeedAppearances true` 由阅读器重建）。

**技术方案**：
- 后端 `get_form_fields(inputPath)` → `Vec<FormField { name, fieldType, value, options, pageIndex, rect }>`：从 Catalog `/AcroForm` `/Fields` 遍历，解析 `/T`（名）、`/FT`（类型）、`/V`（当前值）、`/Opt`（选项）、`/P`（所在页）。
- 后端 `fill_form(req { inputPath, outputPath, values: Vec<{ name, value }> })`：按 fully-qualified name 匹配设 `/V`（文本 = String、复选框 = `/Yes`|`/Off`）；AcroForm 设 `/NeedAppearances true`。
- 前端：表单工具 `form` 面板：加载 → 按类型渲染控件 → 填写 → 另存（非就地编辑，不进 undo）。

**任务清单**：
- [ ] 后端两个命令 + 单测（程序化构造含 AcroForm 的测试 PDF → fill → 断言 /V 与 NeedAppearances）
- [ ] 前端表单面板（按字段类型渲染 + 填写 + 另存）
- [ ] i18n + README 同步

**验收**：对含表单的 PDF 填写后，在阅读器中值正确显示；无表单文件给出友好提示。

## 功能 4：替换文本（覆盖式）

**目标**：搜索文本 → 列出全部匹配（含位置）→ 勾选后统一替换为新文本。

**范围**：覆盖式替换（白块 + Helvetica 同字号叠加）；不尝试复用原文子集字体；不处理跨行匹配。

**技术方案**：
- 前端：复用 pdfjs `getTextContent` 坐标提取（表格提取同源逻辑）拼接每页文本并记录每字符 bbox → 搜索词匹配 → 合并连续字符 bbox 为匹配框 → 勾选列表。
- 后端 `replace_text(req { inputPath, outputPath, replacements: Vec<{ page, x, y, width, height, fontSize, newText, color? }> })`：单命令内对每条执行「白色覆盖矩形 + 原位新文本」（复用 add_rectangle/add_text_to_page 的内容流与 Resources 机制，每页合并为一次追加），保证撤销一步还原。
- 前端执行走 `applyEditInPlace`。

**任务清单**：
- [ ] 后端命令 + 单测（执行后内容流含覆盖矩形与新文本）
- [ ] 前端搜索/匹配列表/替换执行
- [ ] i18n + README 同步（已知限制改写）

**验收**：对常规文本 PDF 替换后视觉上原文消失、新文本出现在原位置；可撤销。

## 功能 5：PDF 安全（加密/解密，AES-128）

**目标**：为 PDF 设置密码保护（AES-128，R4/V4），以及解除已有密码保护另存。

**范围**：标准安全 handler R4/V4（crypt filter AESV2）；权限位（打印/复制/修改）；不做公钥加密、不做 AES-256。

**技术方案**：
- **Spike 先行**：验证 lopdf 对已加密 PDF 的解密读取（`load_with`/decrypt 能力）与加密写出路径——`Document::save` 不加密任何对象，因此采用**序列化后处理**：正常 `save` 到内存 → 重载解析 → 对每个间接对象的 String/Stream 以每对象密钥 AES-128-CBC 加密 → 写 `/Encrypt` 字典与 trailer `/ID`。
- 后端 `encrypt_pdf(req { inputPath, outputPath, userPassword?, ownerPassword, permissions })` 与 `decrypt_pdf(req { inputPath, outputPath, password? })`，实现置于新模块 `src-tauri/src/commands/security.rs`（算法独立、避免 pdf_ops.rs 继续膨胀）。
- 新依赖（经 rsproxy 镜像添加）：`md-5`、`aes`、`cbc`、`sha2`。
- 前端：安全工具 `security` 面板：加密（用户/所有者密码 + 权限勾选）/ 解密（输入密码另存）。
- **风险与备选**：加密后处理路径若与 lopdf 序列化细节冲突，降级 RC4-128（算法子集，同一框架）或在此记录部分完成，不阻塞其余四项。

**任务清单**：
- [ ] Spike：lopdf 解密读取 + 加密后处理可行性验证
- [ ] security.rs：R4 密钥派生（Algorithm 3.2/3.1）+ 每对象密钥 + AESV2 加密 + /Encrypt 字典
- [ ] encrypt_pdf / decrypt_pdf 命令 + roundtrip 单测（加密后无密码加载失败、带密码成功；解密后免密可读）
- [ ] 前端面板 + i18n + README 同步

**验收**：加密文件无密码打不开、密码正确可打开且权限生效；解密输出可被任意阅读器免密打开。
