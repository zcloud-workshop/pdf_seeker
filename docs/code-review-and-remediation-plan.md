# PDF Seeker 全项目审查与整改计划

审查日期: 2026-09-27. 基线: `6e73574`, 应用版本 `0.4.0`.

本文记录代码, 业务逻辑, 功能设计和交付流程的审查结果. 本次仅新增审查文档, 未实施下列业务代码整改. 所有未勾选项目均为待办, 不继承旧版本计划中的完成状态.

实施分工入口: [分工总览与合并规则](remediation/README.md). 已按文件归属拆为 6 个可并行实施包, 另有 1 个后续协议联调与发布验收包. 多人领取以新入口的边界、依赖和验收规则为准; 本文保留审查证据, 第 6 节阶段计划作为原始建议保留, 不再直接按 S0-S5 分配并行开发. 拆分不表示问题已经修复.

## 1. 结论与执行重点

项目已具备较完整的功能入口, 但当前主要问题是数据正确性和功能闭环, 不适合优先继续增加工具数量. 最应先解决的是连续编辑破坏 PDF 内容, 页树变更错误, 文件写入竞争, 工具状态跨文件串用, 以及 S3 配置和浏览链路断裂.

建议下一轮以稳定性修复为目标. 先保护原文件并建立真实 PDF 回归样本, 然后修复既有功能, 最后拆分大模块和优化性能. 保留 Tauri + Svelte + Rust 架构, 无需整体重写.

已有值得保留的实现包括: 本地优先的 PDF 处理, 配置与最近文件统一持久化, 标签页派生状态, S3 文件列表分页, 插件参数直接传给进程, PDF 真实批注和书签对象写入, 更新签名验证配置. 下文关注这些实现尚未闭合的边界.

优先级定义:

| 等级 | 含义 | 建议门禁 |
| --- | --- | --- |
| P1 | 可破坏文档, 混入错误数据, 阻断核心功能或错误发布 | 下一次稳定版发布前完成 |
| P2 | 特定文档兼容性, 生命周期, 性能或交互缺陷 | 紧随 P1 的稳定性迭代完成 |
| P3 | 可维护性, 体验和能力扩展建议 | 在正确性回归建立后安排 |

证据标签:

- **复现**: 本轮执行了最小验证程序, 观察到问题.
- **源码确认**: 调用链能直接证明问题, 尚未在完整桌面界面复现.
- **设计限制**: 实现确实存在该边界, 需调整产品承诺或另行设计.
- **待验证**: 缺少外部服务, 独立阅读器或运行样本, 不按已证实故障计算.

## 3. 问题清单与具体整改

以下位置均相对于仓库根目录, 行号对应上述基线. 每项给出触发方式, 整改范围和可执行验收条件.

### R01 [P1, 源码确认] 通用 Input 未绑定原生输入值

- 位置: `src/lib/components/ui/Input.svelte:9`, `:12`; `src/views/Settings.svelte:300` 起的调用点.
- 发现: 组件解构了 `value = $bindable("")`, 但 `<input>` 仅展开剩余属性. `value` 既未传入 DOM, 也未双向绑定. 设置页大量 `bind:value` 因而不能可靠读写字段, 已保存值也无法显示. 使用显式 onchange 的部分调用可以接收事件, 但仍缺少受控回显.
- 整改: 在原生输入框上建立值绑定, 保留事件透传. 检查 number/password/text 三类调用, 不通过逐个表单绕过组件问题.
- 验收: S3 endpoint, bucket, 密钥修改后实际保存新值; 重进设置正确回显; 父状态主动变化更新输入框, 用户输入更新父状态.

### R02 [P1, 复现] 连续编辑破坏 Contents 结构

- 位置: `src-tauri/src/commands/pdf_ops.rs:1067`, 同类逻辑在 `:567`, `:826`, `:1144`, `:1245`, `:1918`.
- 发现: 将已有 Contents 数组包装为间接对象再加入新数组, 产生数组引用数组, 而非扁平的内容流引用列表. 连续追加 `FIRST` 和 `SECOND` 后, 最小验证读取页面内容只保留 `SECOND`.
- 影响: 添加文字, 水印, 签名, 矩形, 高亮和覆盖式替换可能让原页面或先前编辑内容无法解析.
- 整改: 统一小型内容流追加函数, 解引用并规范化单流, 内联数组和间接数组, 始终保持合法结构. 不未经检查就替换成另一个同样无法展开间接数组的库函数.
- 验收: 三类 Contents 输入各连续执行三次混合编辑, 原文和全部新增内容均能提取及独立渲染.

### R03 [P1, 复现] PNG 图像流声明与字节不一致

- 位置: `src-tauri/src/commands/pdf_ops.rs:184`, `:195`; 图片转 PDF 调用 `:637`, 签名调用 `:765`.
- 发现: RGB/alpha 原始像素直接写入带 `/FlateDecode` 的流. 2x2 RGBA 样本的 RGB 与 SMask 都没有真实压缩. lopdf 保存并不会自动修复这类声明.
- 整改: 字节编码和 Filter 必须匹配, 先创建原始流再使用实际压缩过程. 同时核对 `:167` 对 JPEG 一律声明 DeviceRGB 的做法, 按真实通道处理灰度图.
- 验收: RGB/RGBA PNG, 灰度 JPEG 和透明签名均正确显示, 原图颜色与透明度正确, 不以文件存在作为通过标准.

### R04 [P1, 复现/源码确认] 合并, 插入, 重排的页树处理不完整

- 位置: `src-tauri/src/commands/pdf_ops.rs:254`, `:308`, `:678`, `:712`, `:734`.
- 发现: 手算重编号映射与 lopdf 的实际页序重编号不一致, 已复现逆序对象 ID 的页面被错误排序. 插入按全部叶页面数校验位置, 却按根 Kids 长度执行插入, 已复现三页嵌套页树在位置 2 插入时 panic.
- 另有确认问题: `[1,1,3]` 可以通过三页重排校验; 修改 Kids 后未完整维护 Parent/Count. `insert_pages` 当前没有前端调用入口, 属于已注册后端命令缺陷; 合并, 重排直接影响现有 UI.
- 整改: 重编号后读取实际 `get_pages()` 结果; 规范化页树或按叶页面定位插入; 同步 Parent/Kids/Count 及继承属性; 严格校验完整唯一排列.
- 验收: 非零 generation, 页序与对象 ID 逆序, 两/三层页树, 首中尾插入全部正确; 重复/缺失页输入拒绝且不写文件; 修改后双向页树关系一致.

### R05 [P1, 源码确认] 编辑覆盖原有字体和图像资源

- 位置: `src-tauri/src/commands/pdf_ops.rs:793`, `:805`, `:812`, `:519`, `:1029`, `:1209`, `:1883`.
- 发现: 签名可能用仅含 SigImg 的字典替换整个 XObject, 原图像资源丢失; 内联 Resources 分支又可能不添加 SigImg. 文字等操作固定写 F1/GS1, 会与既有资源冲突; 继承资源, 间接资源子字典和多页共享资源处理不完整.
- 整改: 复用有效页面资源解析, 保留继承内容, 对共享资源复制后修改, 为新增资源分配唯一名字, 支持直接和间接字典.
- 验收: 已有 F1/GS1/图像, 多页共享资源, 父级继承资源, 内联和引用字典样本均通过. 修改目标页不能改变非目标页或旧内容.

### R06 [P1, 源码确认] 文件保存和撤销缺少统一事务

- 位置: `src-tauri/src/commands/pdf_ops.rs:114`; `src-tauri/src/commands/security.rs:260`, `:335`; `src/views/Tools.svelte:1232`, `:1261`, `:1277`, `:1293`.
- 发现: PDF 保存直接截断目标文件再写, 同路径编辑遇到磁盘满/进程中断可能损坏原件. 快捷键撤销未检查 busy, undo/redo 本身无互斥, 可与正在写入的命令交错; 写入失败还可能已经弹出历史记录.
- 整改: 所有写 PDF 路径统一为同目录临时输出, 必要的刷盘, 可读性检查和平台适配的原子替换. 编辑/撤销/重做按文件身份串行执行, 成功后提交历史, 失败保留原文件和历史. 写前核对文件版本以发现外部修改.
- 验收: 延迟写入期间连续撤销不产生并发写; 注入写入/替换失败后原文件字节不变且可重试; 关闭标签不能使在途任务写到另一文件. Windows 上也要验证覆盖语义.

### R07 [P1, 源码确认] 工具结果与实际提交文件可能不一致

- 位置: `src/views/Tools.svelte:1224`, `:1457`, `:1578`, `:1665`; `src/lib/components/layout/TabBar.svelte:41`, `:81`.
- 发现: 在 A 的工具页加载表单或替换匹配后关闭 A, 活动文件变为 B, 但仅清空 undo/redo. 旧缩略图, 匹配坐标和表单字段仍属于 A, 提交读取的路径却是 B. 无文件时进入重排工具再 Open PDF 也不会自动加载缩略图.
- 整改: 结果携带源文件身份和内容版本; 换文件清空并重载全部文档状态; 提交校验身份; 拒绝过期异步回调. 复用一个打开文档入口.
- 验收: A/B 标签切换, 关闭活动标签, 任务过程中换文件, 均不能把 A 的操作应用到 B; 初次打开自动加载当前工具需要的数据.

### R08 [P2, 源码确认] 编辑坐标和页面几何未统一

- 位置: `src/views/Tools.svelte:144`, `:217`, `:396`; `src-tauri/src/commands/pdf_ops.rs:224`, `:324`, `:1307`.

- 整改: 统一解析继承属性, 浮点尺寸, 非零原点和旋转; 预览与写入使用同一可逆坐标转换. 校验旋转角, 裁剪范围及其他几何输入.
- 验收: 0/90/180/270 度, 浮点 A4, 非零 CropBox/MediaBox 和父级继承样本, 四角点击/拖框写入与预览一致.

### R09 [P2, 源码确认] PDF 文本编码与绘图状态不完整

- 位置: `src-tauri/src/commands/pdf_ops.rs:479`, `:1008`, `:1114`, `:1439`, `:1491`, `:1732`, `:1858`; 可复用 `:1971` 的书签编码函数.

- 验收: 中文批注/字段名/字段值往返正确, 中英文页面文字跨阅读器可见; 连续混合绘制不改变已有颜色, 线宽和变换.

### R10 [P2, 源码确认] 表单读取, 编辑和外观能力不一致

- 位置: `src/views/Tools.svelte:1437`, `:1466`; `src-tauri/src/commands/pdf_ops.rs:1534`, `:1591`, `:1686`, `:1709`, `:1735`, `:1752`.

### R11 [P1, 源码确认] 书签保存可能丢子树, 撤销快照被刷新清空

- 位置: `src/lib/components/viewer/PdfScroller.svelte:413`, `:435`, `:566`, `:586`, `:590`, `:138`; `src-tauri/src/commands/pdf_ops.rs:2035`.

### R12 [P2, 源码确认] 编辑历史与阅读状态绑定视图生命周期

- 位置: `src/App.svelte:30`; `src/views/Tools.svelte:78`, `:1218`, `:1294`, `:1595`, `:3224`; `src/lib/components/viewer/PdfScroller.svelte:67`.

- 验收: 跨视图, 跨工具, 同文件标签激活后状态保留; 替换面板可以撤销/重做; 输入框 Cmd+Z 不修改 PDF. 关闭文档时按明确规则释放历史.

- 整改方向: 最小可用 CSP/capability, 明确插件可信边界; 认证模式分别构建客户端; 更新任务统一状态和进度, 提供诊断原因及编辑任务繁忙时的重启协调.
- 验收: 匿名/静态/环境三模式和不同 endpoint 的契约测试; 不可信内容不能随意触达本机命令; 错误签名, 离线, 取消, 重复检查都有可理解结果. 本轮没有证明存在可远程利用的漏洞, 也没有验证线上更新一定可用.

## 4. 功能设计调整建议

### 4.1 建立清晰的文档生命周期

当前就地写入是已公开行为, 整改不应静默改变用户工作流. 第一阶段保持既有入口, 加入安全提交, 统一历史和失败恢复. 若后续改为工作副本编辑, 应明确提示保存/另存为语义并提供迁移说明.

建议文档会话至少管理: 文件身份, 版本/修改时间, 当前页, 缩放, 编辑历史, 在途任务与错误. 预览和工具读取会话状态, 不分别持有互相矛盾的文件路径. 历史从组件移出后, 关闭文档和退出应用的释放规则必须明确.

### 4.2 明确功能名称与真实能力

| 功能 | 当前边界 | 建议产品表达与后续路线 |
| --- | --- | --- |
| 替换文字 | 白块覆盖后叠字, 原始文字仍存在; 现 UI 已标 overlay | 明确保留原文可搜索/提取, 不用于脱敏; 真替换/擦除另立需求 |
| 签署 | 插入签名图片 | 明确为图片签名, 不暗示具有证书身份验证和篡改检测 |
| 压缩 | 现有 PDF 对象/流处理能力 | 展示前后大小, 不保证一定缩小; 有损图像压缩作为独立选项 |
| OCR | 文字层提取与外部 OCR 混用 | 展示逐页处理方式, 缺失语言包和失败页; 不用一个全文长度阈值判定全部页 |
| 表格提取 | 坐标启发式, 合并/空单元格复杂 | 提供导出前表格预览及列修正; 扫描件先 OCR, 明确非结构化识别结果 |
| PDF 对比 | 同页号文字 diff 与并排查看 | 不把无文字层相同解释为视觉相同; 页对齐和像素差异分阶段增加 |
| 云同步 | 保存设置时备份配置 | 名称改为配置备份更准确; 不暗示 PDF 文件自动同步或双向冲突合并 |
| 版本保留 | 展示查询参数, 尚无清理 | 删除未兑现的保留承诺, 实现前不要触发自动远端删除 |
| PDF 安全 | RC4-128, 兼容范围有限 | 明示兼容模式和不支持算法, 通过依赖调研决定现代加密路线 |

### 4.3 任务与错误反馈

先覆盖 PDF 批量导出, OCR, S3 传输和插件这些确实耗时的流程. 状态采用准备/执行/完成/部分失败/取消/失败, 结果显示目标文件, 处理页和实际输出路径. 取消必须定义能否保留已完成产物, 不能仅隐藏 loading.

应用层保留可读错误, 同时区分文件损坏, 权限不足, 写入失败, 密码错误, 不支持特性, 网络错误. 日志不包含密钥, 密码, 文档正文或完整云端签名 URL. 当前 tracing 依赖已存在但未形成完整诊断闭环, 应围绕真实任务错误接入, 不增加无目的日志.

## 5. 最小架构整改方案

按责任拆分现有大文件, 不先造通用插件框架或复杂命令总线.

| 边界 | 内容 | 复用/迁移原则 |
| --- | --- | --- |
| 文档会话 | 文件身份, 阅读状态, 版本, 历史, 写入互斥 | 从 stores 和现有历史迁移, 一个文件只有一个写入事务 |
| PDF 基础操作 | 有效资源, Contents, 页树, 几何, 文本编码, 原子保存 | 先提取被多个已确认缺陷共同需要的小函数 |
| 工具面板 | 页面组织, 标注, 表单, 转换/OCR, 安全, 插件 | Tools 保留导航和任务状态, 各面板只处理自己的参数与操作 |
| PDF 渲染生命周期 | 加载/释放, 过期请求, 可视窗口, 缓存预算 | 阅读器和预览复用明确接口, 不共享易冲突的全局 canvas 状态 |
| IPC 契约 | 请求/响应类型及序列化样本 | 先统一 S3 命名和错误结构; 类型生成是否引入另行评估 |
| 配置与 S3 | 配置事务, 密钥引用, 对象键, 备份格式 | 复用已有 sync_key 思路统一键构造, 避免多处复制前缀拼接 |

每次提取前执行三问: 是否为最简单方案, 是否只覆盖当前问题, 是否符合现有代码风格. 先补行为回归再移动逻辑, 不在一个提交中同时重写 UI, 算法和持久化格式.

## 7. 验收矩阵与测试策略

优先测试可观察行为和已确认失败路径, 不编写仅复述实现的断言. UI 测试覆盖 Input, 文档切换, 撤销, 异步过期结果和 DTO 消费; Rust 测试覆盖结构和文件事务; 少量端到端测试把两者连接起来.

| 样本/环境 | 核心操作 | 必须证明 |
| --- | --- | --- |
| 三种 Contents 结构 | 连续文字/矩形/水印/替换 | 原内容与各次修改同时保留 |
| RGBA PNG, 灰度 JPEG, 含原图像 PDF | 图片转换, 签名 | 透明度/颜色正确且原图不丢 |
| 多层页树, 逆序对象 ID, 非零 generation | 合并, 插入, 重排, 删除, 提取 | 页序, 内容, Parent/Kids/Count 一致 |
| 继承/共享/间接 Resources | 添加内容 | 不覆盖旧资源和非目标页 |
| 旋转, 非零原点, 浮点页面尺寸 | 点击, 拖框, 裁剪 | 保存结果与预览坐标一致 |
| 中文文字, 批注, 书签, 表单 | 编辑并跨阅读器打开 | 编码, 字形, 值和可见外观一致 |
| 无目标父书签, 外部链接 | 改名, 排序, 撤销 | 未改节点及完整子树保持 |
| 两文件, 在途写入, 外部修改 | 切换/关闭/撤销/写入失败 | 不串文件, 不丢历史, 冲突可见 |
| 10 页后 2 页 OCR, 混合扫描 | 连续任务, 缺失引擎, 页失败 | 不串数据, 不漏报失败, 临时文件清理 |
| 测试桶的空/非空前缀与多版本 | 上传, 下载, 导航, 删除 | key 与 DTO 一致, 精确版本操作 |
| 断网, 损坏备份, 并发配置修改 | 备份/恢复/保存 | 时间真实, 原配置可恢复, 内存磁盘一致 |
| 中文大输出, 孙进程, 失败产物插件 | 执行和超时 | 输出不 panic, 内存有界, 超时实际结束 |
| 1000 页扫描文档, 长文本对比 | 滚动, 缩放, 快速换文件 | 首屏/内存/响应有基准, 不显示过期结果 |
| macOS/Windows/Linux 与测试发布 | 打包, 更新, 重启, 失败恢复 | 版本与签名正确, 无不可恢复的文件破坏 |

真实 PDF 验证不能只用 lopdf 生成再用 lopdf 读取. 至少选一个独立解析/渲染实现, 配合应用内 pdfjs 和平台阅读器检查. 加密应加入另一实现产生的文件, 表单应包含真实 Widget/AP. 性能样本与业务样本均使用合成或脱敏文件, 不把用户文档提交仓库.

每条问题关闭时记录: 修复文件, 触发样本, 测试命令/结果, 独立阅读器结果(适用时), 残余限制. P1 关闭前不得只凭编译通过或文件生成成功标记完成.
