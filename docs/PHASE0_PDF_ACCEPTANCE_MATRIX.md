# Phase 0 PDF 写入验收矩阵

> 状态：执行中  
> 目的：将“PDF 能编译/能重开”提升为“真实文档可安全交付”。  
> 原则：任何写入型能力在通过对应矩阵前保持实验性，失败不得覆盖原件。

## 1. 自动化基线

CI 已覆盖下列最低契约：

- `lopdf` 重开生成输出；
- CI 中对 fixture command 输出运行 `qpdf --check`；
- CI 中使用 Poppler 渲染输出第一页；
- 新输出路径可不存在；
- 输出不得等于任何输入路径；
- 批量编辑后的原始与新增文本均可提取；
- 旋转页和 `/Contents` 数组中的多内容流可以保留。

自动化 fixture 仅用于结构和确定性回归，不能替代真实文档人工验收。

## 2. 真实样本集

样本必须合法取得、脱敏并保存在不提交到仓库的位置。每类至少准备一个样本：

| 编号 | 样本类型 | 必须具备的特征 |
|---|---|---|
| R1 | 数字文本 PDF | 多页、页码、英文或西文段落 |
| R2 | 中文文本 PDF | 嵌入或子集中文字体、多个段落 |
| R3 | 图片型 PDF | 每页至少一张彩色图片 |
| R4 | 复杂页面树 | 不同页尺寸、已有 `/Rotate`、不同 Resources 结构 |
| R5 | 扫描件 | 倾斜或低对比度页面，供 OCR 使用 |
| R6 | 表格文档 | 常规表格和至少一个复杂表格 |
| R7 | 已加密文档 | 合法测试密码；仅验证识别和清晰错误提示 |
| R8 | 损坏输入 | 截断 xref 或缺失对象；仅验证失败不产生最终输出 |

记录每个样本的来源类别、页数、大小、SHA-256 与预期限制；不要提交真实客户文件、密码或私钥。

## 3. 验收操作矩阵

| 能力 | 自动化结构验收 | 人工视觉验收 | 完成条件 |
|---|---|---|---|
| 合并 | 页数、输入顺序、qpdf、Poppler | 页眉页脚、图片、字体无丢失 | 所有 R1–R4 输出可打开，顺序正确 |
| 拆分/抽取 | 页数、范围、qpdf | 每个输出页视觉一致 | R1–R4 每个范围均正确 |
| 旋转 | `/Rotate`、qpdf、Poppler | 方向、文字方向、图片方向 | R1–R4 90/180/270° 均正确 |
| 删除/重排 | 页数、顺序、qpdf | 缩略图与正文顺序一致 | R1–R4 无重复或遗漏页 |
| 插入页面 | 目标/源页数、文本顺序、qpdf | 插入位置、字体和图片保留 | R1–R4 目标和源组合均正确 |
| 压缩 | 可重开、前后大小 | 图片清晰度、文本可读性 | 明确预设的大小/质量结果可解释 |
| 水印 | 可重开、qpdf | 位置、角度、透明度、跨页一致 | R1–R4 视觉结果符合参数 |
| 视觉签名 | 可重开、资源保留 | 原图片不消失、签名位置正确 | R3/R4 原有图片与签名均存在 |
| 添加文字/矩形/高亮 | 原始/新增文本、qpdf、Poppler | 位置、颜色、透明度、字体 | R1/R2/R4 结果符合预览 |
| OCR | 模型状态、输出文件可打开 | 中文/英文识别、倾斜页质量 | R5 有可记录的准确率基线 |
| 密码文档 | 正确识别/明确错误 | 不尝试写入或误报可解密 | R7 不泄露密码、不生成伪成功输出 |
| 损坏输入 | 命令失败、无最终文件 | 不覆盖任何原始文件 | R8 所有写入命令安全失败 |

## 4. 每次验收步骤

1. 计算输入文件 SHA-256 并记录页数、大小；
2. 选择新输出文件名，不允许与输入相同；
3. 执行单一操作，记录参数；
4. 确认输出出现且输入 SHA-256 未变；
5. 用应用自身重新打开输出；
6. 在 CI/本地可用时运行 `qpdf --check <output>`；
7. 用系统 PDF 阅读器和 Poppler/PDF.js 渲染人工对比关键页；
8. 记录通过、失败、样本编号、平台和构建版本；
9. 对失败样本新增可复现 fixture 或最小化测试，不只修复当前文件。

## 5. 发布判定

- **页面操作可发布**：合并、拆分、旋转、删除、抽取、重排、插页在 R1–R4 全部通过；
- **编辑功能可发布**：文字、矩形、高亮、水印、签名在对应 R1–R4 样本中结构与视觉全部通过；
- **OCR 可发布**：R5 识别指标、模型安装/离线运行、失败恢复均已记录；
- **任何一项不通过**：保持功能实验性，README 与 UI 不得标记为可用。
