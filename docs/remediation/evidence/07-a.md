# 07-A 全部写入事务 — 实施证据

分支 `codex/remediation-07-a`,基线 `origin/main` `c9910e0`(01-06 全部合入后)。worktree `../pdf_seeker_07a`。环境: macOS 27 arm64, Node 24.18.0 (nvm), pnpm 11.9.0, rustc 1.95.0。

## 变更

- `src-tauri/src/commands/pdf_ops.rs`: 新增 `pdf_file_fingerprint(path)` 与 `commit_pdf_snapshot(path, snapshot_path, expected_size?, expected_modified_ms?)`。恢复取 `PDF_WRITE_LOCK` → 校验目标 (size, mtime) 指纹(不匹配即拒绝)→ 从快照加载校验 → 复用既有原子保存链(同目录临时文件 + fsync + 重载验证 + 平台替换 + 目录 fsync)→ 返回新指纹。快照临时文件仅在位于系统临时目录内时由后端清理(不做任意路径删除)。`lib.rs` 注册两个命令。
- `src-tauri/src/commands/s3_ops.rs`: `s3_download_file` 的最终 rename 进入 PDF 写锁,下载目标与在途编辑不再交错。
- `src/lib/document/restore.ts`(新): 前端快照字节写入系统临时目录唯一文件后经 `commit_pdf_snapshot` 提交;不再有任何针对 PDF 的 plugin-fs 直写。
- `src/lib/document/session.svelte.ts`: 会话记录指纹基线;`assertFileUnchanged` 写前预检;`anyWriteBusy()` 聚合;`refreshFileFingerprint` 写后刷新。
- `src/views/Tools.svelte`: `applyEditInPlace`/`undoEdit`/`redoEdit` 的 5 处直写(含失败回滚)全部改走后端事务;每次写前预检、成功后刷新指纹。
- `src/lib/components/viewer/PdfScroller.svelte`: 书签保存进入 per-file 写互斥(`beginFileWrite`),快照推入统一会话历史;删除组件本地单级 `outlineUndoSnapshot`;Viewer 的 Cmd+Z / Cmd+Shift+Z 现在撤销/重做该文件的完整编辑历史(含 Tools 编辑与书签保存),恢复走后端事务;`loadDocument` 成功后刷新指纹基线。
- `src/lib/stores/index.ts` + `src/lib/components/layout/TabBar.svelte`: `closeTab` 在写忙时返回 false,标签保留;TabBar 以对话框说明原因(关闭按钮/中键/Cmd+W 三入口)。
- `src/App.svelte`: `onCloseRequested` 在写忙时阻止并确认;原子保存保证文件不会损坏,退出仅放弃在途任务;确认后 `destroy()`。capabilities 相应增加 `core:window:allow-destroy`。
- `src/lib/updater.ts`: 安装(`downloadAndInstall`)与重启(`relaunch`)前检查 `anyWriteBusy()`,忙时置明确错误状态(`updater.busyEditing`)且本次不继续;修复了原实现中下载后状态机的一处分支缺陷(由测试暴露)。
- i18n: 中英各新增 5 键(app.exitWhileEditing[Title]、tabs.closeBlocked[Title]、updater.busyEditing)。
- `vitest.config.ts`: 增加 svelte 插件与 `@`/`$views` 别名(与 vite.config.ts 一致),runes 模块(session/stores)可在 vitest 中导入。

## 语义与残余验收

- 进程内互斥(`PDF_WRITE_LOCK` + per-file `writeBusy`)不等于跨进程文件锁;外部程序在应用运行期间写同一文件的最后写入胜出语义未改变。
- 指纹校验在恢复命令内于锁下强制执行;20 个既有编辑命令保持旧 IPC(不带指纹参数),其外部修改检测依赖前端会话预检(预检与提交之间存在窗口,预检失败即中止,不会覆盖后静默成功)。
- Windows `MoveFileExW` 覆盖语义与 `destroy()` 权限未在 Windows 实机验证。
- GUI 人工场景未执行: 写忙时关标签/退出弹窗、updater 忙提示、Viewer 书签撤销跨视图行为 — 逻辑均有单测,实际交互留待 07-E 三平台复核。
- R06 的前端直写路径至此全部消失;注入失败不损坏原文件、并发快捷键互斥、关闭不串文件在单测层闭合,GUI 层验收待 07-E。
